# 历史 Listing 数据库规范

## 入库条件

只在用户明确确认最终稿后入库。草稿、未确认版本、竞品文案和仅供讨论的样稿不进入正式历史库。

## 每条记录字段

- 产品名称与 SKU / ASIN（如适用）
- 站点、商品类型、品牌
- 主要产品事实及证据来源
- 已验证卖点、待确认信息、适用限制
- 最终 Title
- 最终 Item Highlights（如适用）
- 最终 Bullet Points（保留每条独立字段）
- 最终 Product Description
- 最终 Backend Search Terms
- 使用的核心卖点、购买意图和场景
- 关键词清单及字段分配
- 禁止词检查结果和平台规则版本
- 确认日期、版本号、修改摘要

## 查重规则

与历史已确认 Listing 分字段进行比较，并报告最相似历史 SKU/版本、命中字段、相似片段和相似度。

| 字段 | 用户指定阈值 |
|---|---:|
| Title | < 50% |
| Item Highlights | < 40% |
| Keywords | < 40% |
| Bullet Points、Description 及其他正文 | < 30% |

相似度计算方法在 Skill 实现阶段明确并保持固定，结果用于提醒人工判断，不能只依赖单一字符重合率。短字段样本少时应标注结果不稳定。若超过阈值，调整表达和内容组织，同时保留产品准确性。

## 文件维护

每个确认版本保留可追溯记录，不覆盖旧版。文件名或数据库主键包含 SKU、站点和版本。更新时记录确认日期、变更原因及关联产品事实，便于后续差异化审查。

## Listing 写作流程与确认点

### 新写任务

收到产品档案及本次任务信息后，先形成基础大纲。对候选卖点核实真实性和适用条件，映射对应买家需求，去除重复内容，结合关键词相关性排序，并将卖点与场景分配至字段。先向用户展示写作规划，确认后再输出 Listing 文字版。

### 翻新任务

先将原 Listing 拆为保留、优化、删除、新增四类，并输出对照规划。原文中有效信息和关键词应获得保护。没有排名或转化数据时，不得推断关键词无价值。以原 Listing 为基础补充调整，目标是与其自身原文保持高于 60% 的内容重复/保留程度。该目标仅适用于原文与翻新稿之间的连续性。

### 统一确认流程

Listing 文字版输出前，先给出本次使用的卖点、人群、场景、关键词、字段位置和优先级，供用户确认或修改。用户确认规划后再生成文字版。只有用户明确提出“输出 Word 文档”后，才生成 Word 文档。

### 最终审核关卡

每次生成后逐项审核，并提供问题位置、风险原因和修改建议：

- 是否出现产品资料没有的功能。
- 是否把竞品卖点错误应用到自有 SKU。
- 是否有未经证实的性能承诺。
- 是否命中公司禁止词或其他限制性表达。
- 是否存在夸大宣传。
- 使用场景是否正确并符合产品条件。
- 文案是否与尺寸、材质、安装方式冲突。
- 标题、要点、关键词长度格式与平台及公司规则是否匹配。

审核结果应列出具体问题，不能只给 Pass / Fail。Amazon 官方要求商品页面信息准确、可信，并遵循对应政策和类目风格指南。

## 历史差异化检查

文本重复率低于 30% 是公司内部差异化目标，不是 Amazon 官方重复率限制。相同品类的基础功能词可能合理重复，不能仅凭通用短语判定文案失败。

每次生成后从三个维度检查：

1. 文本重复：句子、短语和连续词组复用程度。公司目标低于 30%。
2. 语义相似：是否只替换同义词但表达相同内容。超过内部预警阈值时要求复核，阈值在实现阶段另行设定并保持一致。
3. 结构重复：五点卖点排序、场景组织和论述逻辑是否高度相似，是否只是套用历史模板。

历史对比分两级：同系列木纹产品重点比较卖点组织、场景与表达；全部历史 Listing 检查大段文案复用。差异化检查不能驱使文案使用不自然英语或改变产品事实。

翻新任务另行检查翻新稿与其来源 Listing 的连续性，目标高于 60%。这与新稿对其他历史 Listing 的低重复目标属于不同比较对象，不相互替代。

## 数据库结构补充

历史库需保留系列关系、源 Listing ID、最终版本、任务类型（新写/翻新）、跨历史文本重复结果、语义预警、结构相似提示及最终人工处理记录。
