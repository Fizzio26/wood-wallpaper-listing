# Historical listing records

History begins empty. Add a record only after the user explicitly confirms the final listing. Never store drafts, competitor copy, or unconfirmed proposals as final history.

Store one JSON file per confirmed version under the project's `history/` directory when available. Preserve previous versions. Include product/SKU, marketplace, product type, brand, task type, source listing ID for renovations, verified facts and evidence, title, highlights, each bullet separately, description, backend keywords, selling points/scenarios, confirmation date, version, prohibited-word result, policy snapshot date, and change notes.

Compare by field. Company thresholds are title <50%, highlights <40%, keywords <40%, bullets/description/other body <30%. Treat these as internal differentiation thresholds, not Amazon limits. Report exact metric and comparison set. Compare same-series listings for benefit order, scenarios, and phrasing, then all history for substantial reuse. Also assess semantic and structural similarity as model judgments. If a semantic/structural concern appears, explain it without inventing a numeric score.

Renovation source-continuity target is over 60% with its own original listing. This is a separate comparison from cross-listing differentiation. Preserve useful existing keywords absent ranking/conversion data.
